# FastMoss 达人合并 · V1.3

基于上传的 `app(3).py`（V1.2）升级，保留全部六渠道、筛选、去重与历史排除功能。V1.3 **兼容新旧两种黑马达人榜表头**，无需新增渠道或数据库。

## 部署方式

将本目录的三个文件直接上传至 GitHub 仓库根目录：

```text
app.py
requirements.txt
README.md
```

在 Streamlit Community Cloud 选择对应仓库，`Main file path` 选择 `app.py` 并部署。旧仓库直接覆盖 `app.py` 即可，`requirements.txt` 继续使用现有版本也行。

本地运行：

```bash
pip install -r requirements.txt
streamlit run app.py
```

## 页面输入（3 个上传区）

1. **今日 FastMoss 表格（主要上传区）**：必传，支持多文件 `.xlsx / .xls / .csv`，由程序按表头自动识别渠道。
2. **单日重点建联达人（可选）**：支持同时上传多个 `.xlsx / .xls / .csv`；从各文件**第一张 Sheet** 的 `达人ID` 字段汇总排除名单，不按昵称筛选。
3. **近期全渠道汇总（可选）**：支持上传 1 份**双 Sheet Excel**（`.xlsx / .xls`）；**只读取第一个 Sheet（全渠道达人）**，第二个 Sheet（排除后达人）的ID完全不参与本次排除。文件少于两张 Sheet 或 Sheet 1 无 `达人ID` 会显示错误并阻止下载最终全渠道文件，避免错误排除。

后两个输入区都属于“排除记录（可选）”区域；它们**不进入六渠道识别区**，不改变本次完整汇总。

## 输出规则

- **分渠道下载**：保持旧版规则，每个成功识别的渠道独立筛选、去重、预览和单 Sheet 下载。
- **不传任何排除文件**：全渠道下载为旧版**单 Sheet**，名为 `全渠道达人`。
- **传入至少一份排除文件**：全渠道下载为**双 Sheet**：
  - `全渠道达人`（Sheet 1）：本次六渠道数据的完整全渠道去重结果，**不受排除操作影响**。
  - `排除后达人`（Sheet 2）：从当前 Sheet 1 排除“重点建联表 + 历史全渠道 Sheet 1”的达人ID（先合并去重后排除）。保留 Sheet 1 的全部字段。

- 排除匹配采用达人ID，忽略前面的 `@`，忽略大小写和首尾空格；不使用达人昵称。
- B/C 内的重复达人只影响排除集合一次，不会增加输出行数。
- 本次汇总缺少达人ID的行会保留，并在界面提示无法去重或排除。
- 若某个排除文件解析失败，**不提供最终全渠道结果下载**，直到移除或更正该文件；原有分渠道结果仍可查看和下载。

## 原有六个渠道与可选核心指标

| 渠道 | 核心指标 | 说明 |
|---|---|---|
| 商品关联达人 | 销量、销售额 | 兼容“开始带货时间”全空或缺失 |
| 商品关联视频 | 该商品销量、该商品销售额 | |
| 带货达人榜 | 暂无 | |
| 黑马达人榜 | 暂无 | 兼容旧版「带货潜力指数」和新版「达人搜索」导出格式 |
| 竞品店铺带货达人 | [天]带货销量、[天]带货销售额 | 兼容 `[7天]` 等动态表头 |
| 热门视频 | 暂无 | |

筛选条件默认全部关闭；开启后对应字段采用“≥ 最低值”，且仅筛选**源表实际包含该指标**的数据。

## 日常使用建议

每天上传当天采集的多渠道 FastMoss 表格；在可选区域上传当天/近期已重点建联ID清单及**上一版 App 生成的双 Sheet 全渠道文件**。下载双 Sheet 结果后，用 `排除后达人` 进行新增筛选和建联；需要作为下一次的历史排除依据时，直接上传这份双 Sheet 文件即可，程序仅读取其中的完整 Sheet 1。

**注意**：历史 Sheet 1 包含当时采集的所有达人，因此该规则的含义是“排除近期已经收集过的达人”，并不等同于“仅排除实际发送过建联邀请的达人”。这是用户已确认的方案 A。

运行时文件由应用服务端处理，不写入 GitHub 仓库或外部业务数据库。若部署在云端，请按团队的数据合规与权限要求使用。

## V1.3 升级说明（2026-10-26）

- **黑马达人榜识别**：保留原规则（`带货潜力指数`、`带货总GMV`、`视频带货GMV`、`直播带货GMV`）；另支持经业务确认属于黑马来源的新版字段组合：`达人ID`、`带货倾向`、`近28天销量`、`近28天视频带货销量`、`近28天直播带货销量`。
- **统一字段**：新增 `粉丝总量` → `粉丝数`、`Tiktok达人详情` → `TikTok官网达人主页`。原始各类「近28天...」指标保留原字段名，不与旧版 GMV 字段混合。
- **无变更**：渠道总数仍为六；黑马达人榜无核心指标筛选；其他渠道规则、渠道内/全渠道去重、排除名单与双 Sheet 输出均沿用 V1.2。
- **注意**：新版「达人搜索」表头本身不含可直接证明属于“黑马达人榜”的渠道名。此新增规则适用于用户确认来源的该类文件；若今后从其他页面导出完全相同表头，也会被识别为黑马达人榜，建议注意来源。
- **回归测试**：已检查 8 份实际 FastMoss 示例（含新旧商品关联达人和新旧黑马达人），均成功识别。已测试单日重点建联 ID 排除、六渠道合并和双 Sheet 导出。
